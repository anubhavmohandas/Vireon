# Vireon — Autonomous AppSec Pipeline

> **Band of Agents Hackathon · June 2026**
> Point it at a GitHub repo. Walk away. Come back to a triage report, working patch, and open GitHub PR — generated by 8 agents that argue with each other.

**Live demo:** https://vireon-zeta.vercel.app

---

## What it does

Vireon runs an end-to-end security investigation autonomously:

1. Clones the target repo (or accepts a local path)
2. Fetches real CVEs from OSV.dev and NVD against the dependency stack
3. Runs Semgrep static analysis across Python, JS, secrets, OWASP rules
4. LLM confirms which findings are actually exploitable
5. A Challenger agent argues back — actively tries to disprove findings
6. Confidence fusion decides whether to proceed to patching
7. Remediation generates code patches + dependency bumps
8. Compliance reviews the patch (retries up to 3x if rejected)
9. Verification re-runs Semgrep to confirm the fix works
10. PR Delivery opens a GitHub pull request automatically

No human in the loop. Every decision is logged with timestamp, agent name, confidence score, and reasoning. Live progress streams to a shared Band room and the React dashboard simultaneously.

## The 8 Agents

| # | Agent | Phase | Key output |
|---|-------|-------|-----------|
| 1 | **ThreatIntel** | 1 | CVEs fetched, dependency knowledge graph built |
| 2 | **Static** | 1 | Semgrep findings across the codebase |
| 3 | **Exploitability** | 2 | Which findings are actually reachable |
| 4 | **Challenger** | 3 | Adversarial red-team review — disproves or strengthens |
| 5 | **Remediation** | 4 | Code patches + dep version bumps |
| 6 | **Compliance** | 4 | Security policy gate — approve or retry |
| 7 | **Verification** | 5 | Tests + post-patch Semgrep re-scan |
| 8 | **PR / Delivery** | 5 | GitHub PR with branch, commit, dep bumps applied |

Phases 1 (ThreatIntel + Static) run in parallel. Phase 3 is adversarial — the Challenger has a negative weight in confidence fusion. If fused confidence drops below threshold, the pipeline aborts rather than shipping a false-alarm PR.

## Architecture

```
GitHub URL / Local Path
        │
        ▼
  api/routes/scan.py          ← FastAPI: clones repo, starts background task
        │
        ▼
  coordinator/coordinator.py  ← orchestrates 5 phases, owns retry loop
        │
  ┌─────┴─────┐
  │  Phase 1  │  ThreatIntel + Static (parallel)
  └─────┬─────┘
        │
  ┌─────┴─────┐
  │  Phase 2  │  Exploitability
  └─────┬─────┘
        │
  ┌─────┴─────┐
  │  Phase 3  │  Challenger + confidence fusion
  └─────┬─────┘
        │ (abort if confidence < threshold)
  ┌─────┴─────┐
  │  Phase 4  │  Remediation ⇄ Compliance (loop up to 3x)
  └─────┬─────┘
        │
  ┌─────┴─────┐
  │  Phase 5  │  Verification → PR Delivery
  └───────────┘

  All agents share:   memory/shared_state.py
  All agents post to: Band room (REST) + SQLite (WAL)
  Frontend polls:     FastAPI /api/status/{inv_id}
```

## Quickstart (CLI)

```bash
git clone https://github.com/anubhavmohandas/vireon
cd vireon

python -m venv myvenv
source myvenv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# Fill in FEATHERLESS_API_KEY (free at featherless.ai)
# Add GITHUB_TOKEN + GITHUB_REPO for PR delivery (optional)

python main.py https://github.com/owner/repo
# or a local path:
python main.py /path/to/repo
```

## Quickstart (Web UI)

```bash
# Backend
pip install -r requirements.txt
uvicorn api.main:app --reload

# Frontend (separate terminal)
cd frontend
npm install
npm run dev
```

Open http://localhost:5173 — paste a GitHub URL, hit Scan.

## Band SDK Integration

Each agent extends `BandAgent`. All 8 post live status updates to a shared Band investigation room via REST (`POST /api/v1/agent/chats/{room}/messages`). No blocking WebSocket — agents are task-driven, post and move on.

```python
class ChallengerAgent(BandAgent):
    name = "challenger"
    depends_on = ["exploitability"]

    async def execute(self) -> AgentResult:
        # red-team review of confirmed findings
        return AgentResult(verdict="confirmed", confidence=0.72, ...)
```

Without Band credentials: pipeline runs in local mode, all output goes to console + SQLite.

## Deployment

### Backend — Railway

Push to main. `railway.toml` handles the rest:

```toml
[deploy]
startCommand = "uvicorn api.main:app --host 0.0.0.0 --port $PORT"
healthcheckPath = "/health"
```

Required Railway env vars: `FEATHERLESS_API_KEY`, `GITHUB_TOKEN`, `GITHUB_REPO`, `BAND_ROOM_ID`, and all agent ID/key pairs.

### Frontend — Vercel

- **Root Directory:** `frontend/`
- **Framework Preset:** Vite
- **Env var:** `VITE_API_URL=https://<your-railway-url>`

## Hackathon context

Built for the **Band of Agents Hackathon (June 12–19, 2026)**. The multi-agent war room model — where agents debate rather than just sequence — is the core design thesis. The Challenger is not a filter; it's a pressure test that makes confirmed findings stronger by failing to disprove them.
